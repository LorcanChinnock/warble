# Developer

Read this before changing the `warble` command, links, the socket or Settings › Developer. Back to the [architecture index](../../CLAUDE.md#architecture).

Settings › Developer has a switch for each way in, all off by default, and `RemoteCommand` (WarbleModel, `Remote/`) is the one table of commands behind them: each gives the `AppAction` its button dispatches (`.perform`, `.command`, `.setVolume`, `.selectOutput`), so a command does exactly what the notch does. `warble://` links (`RemoteCommand(url:)`, both the `warble` and `warble-dev` schemes) arrive in `AppDelegate.application(_:open:)` as `.linkOpened`, which `reduce` does only while `AppState.answersLinks` is on (`PreferenceKey.answerLinks`), and `settings?section=` is the effect `.openSettings(section:)`; the section names in `RemoteCommand.settingsSections` must match `SettingsSection`'s raw values. The `warble` command is the `WarbleCLI` target, which depends on WarbleModel only and is bundled as `Contents/MacOS/warble-cli` (a `warble` there would collide with `Warble` on a case-insensitive volume; the Homebrew cask and `CommandLinkRow` link it). It sends its arguments as one `RemoteRequest` line over the Unix socket `agent.sock` in the app's Application Support folder (`RemoteSocketPath`), and `AgentSocket.Server` (WarbleCore) answers with a `RemoteResponse` line. The folder is 0700, the socket 0600, and each peer's user is checked. The server hands each request to `RemoteHandler` (WarbleModel) on the main actor, which parses it with the same `WarbleCommand`, dispatches the same actions and answers `now` with a `NowPlayingSnapshot` built from `AppState`; `output <name>` reads the `AudioOutputs` port to match the name (`AudioOutput.matching`) first. `AppState.listensForCommands` follows `PreferenceKey.commandLine`, and `settle` asks for `.listenForCommands(true)` or `false` once each time it changes, which `PlatformEffects` carries out by opening or closing the socket, so with it off no socket exists and with nothing sent the app does nothing. The command never opens Warble. Try it with `build/WarbleDev.app/Contents/MacOS/warble-cli now` while WarbleDev runs with the setting on, and note that a `defaults write` from Terminal reaches the running app only after it restarts, so turn settings on from the Settings window or before launching.
