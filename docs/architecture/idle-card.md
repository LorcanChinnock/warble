# Idle card

Read this before changing what the notch shows while nothing plays, or the last track played. Back to the [architecture index](../../CLAUDE.md#architecture).

While Idle, each surface is in `NotchState.idle`, its panel exactly over the housing, black on a real one and on a virtual one whose rule is Always (`NotchHousing.isAlwaysShown`), and clear on any other virtual one (the panel sets `ignoresMouseEvents = false` so a clear panel still takes the pointer). Only the housing counts for the hover, as at rest, and `HoverIntent` opens it into Expanded with `NotchCard.idle`, as wide as the player's card and `NotchLayout.idleDrop` below the housing. `NotchState(_:isPlaying:needsAttention:idleHover:)` and `NotchCard(isPlaying:needsAttention:showsDoctor:)` (WarbleModel) decide which state and card each surface draws, through `AppState.notchState(_:)` and `card(_:)`; with `PreferenceKey.idleHover` set to `nothing`, Idle is Hidden and no panel shows, except over a housing set to Always, which stays a blank notch and ignores the pointer. The card shows `AppState.lastPlayed`. Whenever `LastPlayed.changes(from:to:)` says a report is a new track or new art, `reduce` asks for `.remember`, which `EffectRunner` answers off the main thread with the art shrunk to 112 pixels. An answer for a track that's no longer the latest is dropped, and the rest are saved with `.saveLastPlayed` through the `LastPlayedStore` port, `LastPlayedFile` (WarbleCore), to `LastPlayed.json` in Application Support. Saves are chained, so the latest wins, and the preview keeps it only in memory (`LastPlayedInMemory`, WarbleModel, which the tests' fake extends). The art is shrunk by a function `EffectRunner` is given (`LastPlayedFile.remembering`), not by the store. Resume dispatches `.command(.togglePlayPause)`; the art dispatches `.openApp`. Preview it with `open build/WarbleDev.app --args -notchPreviewState idle`, adding `-notchPreviewLastPlayed NO` for the card with nothing played yet.
