# Idle card

Read this before changing what the notch shows while nothing plays, or the last track played. Back to the [architecture index](../../CLAUDE.md#architecture).

While Idle, each surface is in `NotchState.idle`, its panel exactly over the housing, black on a real one and clear on a virtual one (the panel sets `ignoresMouseEvents = false` so a clear panel still takes the pointer). Only the housing counts for the hover, as at rest, and `HoverIntent` opens it into Expanded with `NotchCard.idle`, as wide as the player's card and `NotchLayout.idleDrop` below the housing. `NotchState(_:isPlaying:)` and `NotchCard(isPlaying:)` (WarbleModel) decide which state and card each surface draws, through `AppState.notchState(_:)` and `card(_:)`; the Idle notch always takes the pointer. The card shows `AppState.lastPlayed`. Whenever `LastPlayed.changes(from:to:)` says a report is a new track or new art, `reduce` asks for `.remember`, which `EffectRunner` answers off the main thread with the art shrunk to 112 pixels. An answer for a track that's no longer the latest is dropped, and the rest are saved with `.saveLastPlayed` through the `LastPlayedStore` port, `LastPlayedFile` (WarbleCore), to `LastPlayed.json` in Application Support. Saves are chained, so the latest wins, and the preview keeps it only in memory (`LastPlayedInMemory`, WarbleModel, which the tests' fake extends). The art is shrunk by a function `EffectRunner` is given (`LastPlayedFile.remembering`), not by the store. Resume dispatches `.resumeLastPlayed`, and `reduce` picks what to do: with `AppState.playback` still set, a paused session the app can resume, it sends `.play`; with none, a play command would go nowhere, so it opens the track with `.openLink` when `LastPlayed.link` was saved (a Spotify link opens as its `spotify:` URI, which starts the track in the app, through `LastPlayed.resumeURL`), then Spotify launches and plays with `.launchAndPlay` (`ScriptedPlayer.launchAndPlayScript`, run by `ScriptSource.launchAndPlay`), since it reopens on the track it had, and anything else opens its app with `.openApp`. Only `ScriptSource` fills in `PlaybackState.link` (Spotify's track URI). On a normal install the adapter reports and gives no link, since its `contentItemIdentifier` is an opaque ID such as a GUID, so Spotify resumes through the AppleScript branch. Nothing runs until the click, which is when macOS asks for Automation permission for Spotify, and a refused script falls back to `.openApp`. Music isn't resumed this way, because `play` after a cold launch can start an unrelated track. A track with a link, such as a Spotify one, keeps it when the art arrives later and the second look finds none (`LastPlayedState`), and resume opens it with `.openLink(url)`. Any other app, a browser included, opens its app. The art dispatches `.openApp`. Preview it with `open build/WarbleDev.app --args -notchPreviewState idle`, adding `-notchPreviewLastPlayed NO` for the card with nothing played yet.
