# Welcome and the demo

Read this before changing the first launch, the welcome window or the demo. Back to the [architecture index](../../CLAUDE.md#architecture).

On a first launch `AppDelegate` dispatches `.launched(firstRun:)`, from `Preferences.isFirstLaunch(saved:)`, which reads Warble's saved defaults domain: a Warble with `PreferenceKey.hasSeenWelcome` set, or with any other setting saved, was used before the window existed and never sees it. `Onboarding` (WarbleModel, `Onboarding/`) in `AppState.onboarding` starts the demo, then has `reduce` ask for `.showWelcome` once, when the demo ends (at once if something is already playing), and `PlatformEffects` opens `WelcomeWindow` (`Sources/Warble/Onboarding`): Open at login (`LoginItem`), the menu bar icon and a link to the guide, with no permission asked. Closing it saves `hasSeenWelcome` and dispatches `.welcomeClosed`. It decides nothing and has no deadline. The previews skip it, and to see it again run `defaults delete dev.lorcan.Warble.dev` and launch `WarbleDev`. The demo is `NotchDemo` (WarbleModel, `Onboarding/`) in `AppState.onboarding.demo`: resting with a track, Expanded on the player's card, then `NotchState.hint`, Idle with `NotchLayout.hintDrop` of "Hover here to see what's playing" below (`DemoHint`), each for the time `NotchMotion.demoResting`, `demoExpanded` and `demoHint` gives. It returns its next deadline like `IdleAfterPause`, which joins the store's one timer, so there's none once it ends. While it runs `Onboarding.notchState` and `card` give every notch its step ahead of anything else (`AppState.notchState(_:)` and `card(_:)` ask them first), and `NotchController` shows `DemoTrack` (`Sources/Warble/Notch/Views`) in `PlayerModel` from `AppState.demoTrackStart`, so `AppState.playback` stays what the sources said. A pointer entering a notch, a click, a menu or a report of something playing ends it at once (`endsDemo` in `Reduce.swift`), before the action meets the notch, so the notch carries on as usual.
