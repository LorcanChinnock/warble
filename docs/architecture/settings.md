# Settings

Read this before adding or changing a setting, the Settings window, shortcuts or Open at login. Back to the [architecture index](../../CLAUDE.md#architecture).

Keys and defaults live in WarbleCore `Preferences`. Views read them with `@Setting(PreferenceKey.x)`, which takes the default `Preferences` registers, from the `SettingsStore` (`Sources/Warble/Settings`) in the SwiftUI environment; `NSView(hosting:settings:)` hands it to every hosted view. A test checks every such key has a registered default. `SettingsWindow` opens Settings from the menu bar menu, or when Warble is opened again from Finder: a sidebar of `SettingsSection`s beside a grouped `Form` of standard controls in the system appearance, not the notch's black. It takes a Dock icon while open and drops its content when it closes. Shortcuts has a row for each `WarbleAction` (`ShortcutRow`). `ShortcutRecorder` watches keys and clicks only while it records, and pauses `HotkeyCenter` meanwhile. `ShortcutRecording` (WarbleModel) decides what a pressed key does: cancel, clear, ask for a modifier, refuse a reserved or taken combo, or record it. `HotkeyCenter.start()` registers the shortcuts at launch and again whenever a `hotkey.*` key changes, exclusively, so macOS refuses one another app holds exclusively, and Settings shows it. Open at login is `LoginItem` (`Sources/Warble/Settings`), which reads and sets `SMAppService.mainApp` and stores nothing of its own, so it always matches System Settings › Login Items. A section or row arrives with its feature; Players comes later.
