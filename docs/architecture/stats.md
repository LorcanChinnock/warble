# Listening stats

Read this before changing the listening stats, their file or the Stats section in Settings. Back to the [architecture index](../../CLAUDE.md#architecture).

Settings › Stats › Count what I listen to (`PreferenceKey.stats`, off at first) counts the time each track plays and shows the last seven days. `StatsState` (WarbleModel, `Stats/`) holds the setting, the `ListeningSession` under way and the `WeeklySummary` last loaded. A session is the track being counted (title and artist, so a seek or a repeat of the same track doesn't end it) and when it began. It needs no timer: `StatsState.follow`, which runs at the end of every `reduce`, compares the track playing now with the session's and, when they differ, ends the span at `now` and starts the next. A track counts while it is playing (`rate != 0`) and no hide is pending (`hideAt == nil`), so a pause, a report of nothing, Idle and a track change each end the span at the moment `reduce` saw them, and the gap before the next track isn't counted. A span under `ListenedSpan.shortest` (one second) is dropped, so skipping through tracks records nothing. With the setting off `follow` has nothing to count, and turning it off drops the session unwritten; turning it on while a track plays counts from then. There is no deadline, so nothing waits on a timer, and with nothing playing there is no session.

A finished span goes out as `.recordListening(ListenedSpan)`. `.willQuit`, which `AppDelegate.applicationWillTerminate` dispatches, ends the span under way the same way and stops anything starting again; the delegate then calls `EffectRunner.flushStats()`, which blocks the main thread for up to a second until the writes are done, since nothing runs after quit. `.refreshStats`, which the Stats section sends when it appears and whenever the app becomes active, returns `.loadStats(since:)` for the last 30 days (`WeeklySummary.retention`); the runner answers `.statsLoaded` and `reduce` builds the `WeeklySummary` from the spans at `now`. `.clearStats` empties the summary, moves the session's start to now and returns `.clearStats`. `EffectRunner` chains every record, load and clear on the one `keeping` task, so they run off the main actor in the order they were asked for, as the last-played save does.

`WeeklySummary` is pure: spans that began in the seven days to `now` are added up by artist (spans without an artist count in the total and the tracks only) and by title and artist, the top `listed` (five) of each are kept, and ties are ordered by name so the lists don't shuffle between loads.

`StatsStore` (`App/Ports.swift`) is the port, with `StatsInMemory` for the preview and tests. `StatsFile` (WarbleCore, `Stats/`) is the real one: `Stats.jsonl` in Warble's folder in Application Support, one dated JSON span to a line, so recording is an append. `load(since:)` skips a line it can't read and, when older spans are in the file, rewrites it without them, so the file holds 30 days at most. Nothing is sent anywhere.

`StatsModel` (`Sources/Warble/Settings`) keeps `AppState.weeklySummary` for the SwiftUI view, as `DoctorModel` does the Doctor's checks, and `StatsSettings` draws it. `NotchController` dispatches `.statsChanged` when the preference changes, like the other settings.
