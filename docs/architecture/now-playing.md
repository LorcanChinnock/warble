# Now playing

Read this before touching the adapter, `ScriptSource`, `SourcePriority` or how a report becomes a `PlaybackState`. Back to the [architecture index](../../CLAUDE.md#architecture).

Since macOS 15.4, only Apple-signed processes can read now-playing information through the private MediaRemote framework. Warble bundles ungive/mediaremote-adapter, BSD-3-licensed: `scripts/bundle.sh` builds it with CMake from the `Vendor/mediaremote-adapter` submodule and puts `mediaremote-adapter.pl`, `MediaRemoteAdapter.framework` and `MediaRemoteAdapterTestClient` in `Contents/Resources`, signed but never linked. `AdapterSource` (WarbleCore) runs `/usr/bin/perl <script> <framework> <test client> stream --micros` with absolute paths, since `/usr/bin/perl` is Apple-signed, and each command as its own short run (`send 2`, `seek <microseconds>`). The stream starts behind a small Perl watchdog (`AdapterSource.watched`) that forks, waits on stdin and stops the stream when stdin closes. Warble holds the only write end, so the stream ends with Warble even after `kill -9` or a crash. `AdapterStream` (WarbleModel) turns the stream's lines into a `PlaybackState`; its tests replay output recorded from Safari in `Tests/WarbleModelTests/Playback/Fixtures`. A tab reports WebKit's GPU process as `bundleIdentifier` and the browser as `parentApplicationBundleIdentifier`, so the parent wins. `AdapterSupervisor.backend` says which backend is live and why: the adapter, restarting after an exit, or AppleScript because the adapter isn't bundled or Warble gave up on it; `Doctor.Adapter` is built from it. When the stream exits on its own, `AdapterSupervisor` (WarbleModel) runs `test`, which exits 0 when the adapter still works, before starting it again with a growing delay. `test` times out now and then on a working adapter (exit 3 or 4), so those are retried; other failures stop it until Warble is opened again. CONTRIBUTING.md › Updating the adapter explains how to bump the pin. When more than one app reports playback, `SourcePriority` (WarbleModel) picks the one the notch follows: a pinned app, else the one that started playing last, never one on the ignore list (video calls by default). It takes reports per bundle identifier, so it doesn't care how sources are found. Keep everything that touches it behind the `NowPlayingSource` protocol, so a macOS change means replacing one implementation. A source's reports come in as `.sourceReported(bundleIdentifier:_:)`, and commands reach it only as the `.send` effect, which `EffectRunner` sends to its `source`; the preview track is `PreviewSource`. The protocol, `PlaybackState` and `PlaybackCommand` live in WarbleModel; `PlaybackState.elapsed(at:)` runs the position on from the last report, so the progress bar needs no timer of its own. When the adapter isn't bundled or `AdapterSource` gives up, which ends its `states`, `ScriptSource` (WarbleCore) follows Music and Spotify with AppleScript instead: it reads a player when the player posts its distributed change notification, scripts only a running player, and so asks for Automation permission only then. Never run `osascript` against an app without a timeout, and don't script QuickTime. Spotify gives no artwork for an ad on either path: its script reports `missing value` for the artwork URL and the adapter sends no image. The ad is a different track from the song before it, so the notch shows the placeholder and never the song's art.

## Source chips

`AppState.sources` (`SourcePriority`) and `AppState.reports` hold what each app last reported, and `AppState.playback` is the report of the app it follows. `.sourceReported(bundleIdentifier:_:)` replaces the old single report; a `nil` removes that app. `.followSource(_:)` pins an app until it pauses or stops, and `nil` lets the priority list decide again. `AppState.chips` has one chip for each app playing while more than one is, so a single player has none. A guess at a command stays on `playback` until the followed app reports, and a report from another app doesn't replace it.

`NowPlayingSource.reports` gives each app's state. A source that sees only the player macOS picks gets the default, which turns `states` into reports and ends the earlier app's when another takes over. So today the chips never show: `AdapterSource` waits for a mediaremote-adapter release that streams every app ([#17 feat(player): source chips](https://github.com/LorcanChinnock/warble/issues/17)). Don't patch the adapter or poll it for other apps; override `reports` in `AdapterSource` once it can.
