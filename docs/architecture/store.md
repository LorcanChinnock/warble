# The store

Read this before changing `AppState`, `AppAction`, `reduce`, effects, ports or the timer. Back to the [architecture index](../../CLAUDE.md#architecture).

What the app decides lives in WarbleModel's `App/`. `AppState` holds it, `AppAction` is everything that can happen to it (a source's report, the pointer, a click, a key, a setting changing, a deadline coming due), and `reduce(_:_:now:)` is a pure function from a state and an action to the next state and a list of `AppEffect`s. The state machines (`HoverIntent`, `IdleAfterPause`, `ToastQueue`) are parts of `AppState`, so nothing decides around them, and the selectors `AppState.notchState(_:)` and `card(_:)` give each notch what to draw. A settle pass at the end of `reduce` brings whatever follows from the notches' states up to date, such as Idle being held off while one is open, and asks for each effect once when its reason changes. `Store` runs `reduce` synchronously on the main actor for each `dispatch`, so nothing sits between a hover or a click and the panel: no `Task` hop, no Combine and no async/await on that path. It then calls `onChange(old, new, action)` and arms one timer through the `Scheduler` port for `AppState.deadline`, the earliest of every part's deadlines, or none when nothing is due. That's where "no timers while nothing plays" is kept, and a test checks it. Effects are data. `EffectRunner` (WarbleModel) carries out the ones that go through a port, off the main actor where they're slow, and sends the answers back as actions; it hands the rest to `PlatformEffects` (`Sources/Warble/App`), which needs AppKit. Ports are protocols in `App/Ports.swift`: `WallClock`, `Scheduler`, `HotkeyRegistrar`, `DisplayProvider`, `VolumeControl`, `AudioOutputs`, `LastPlayedStore`, `LyricsProvider`, and `AudioTap`, beside `NowPlayingSource`. Their real implementations live in WarbleCore or the app and their fakes in `Tests/WarbleModelTests/App/Fakes.swift`; add one only when a test needs a fake. `AppEnvironment` (`Sources/Warble/App`) is the composition root: `AppDelegate` builds it once and passes it down, and views read its objects from the SwiftUI environment (`View.inject(_:)`), so no type of Warble's own has a shared instance. Each target is split into feature folders (`App`, `Playback`, `Notch`, `Idle`, `Toasts`, `Doctor`, `Shortcuts`, `Displays`, `Volume`, `Design`, `Settings`), and CONTRIBUTING.md › Adding a feature lists what a feature adds.
