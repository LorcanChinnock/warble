# Sleep timer

Read this before changing the sleep timer. Back to the [architecture index](../../CLAUDE.md#architecture).

With `PreferenceKey.sleepTimer` on (it starts off), the player's card has a sleep timer button (`SleepTimerButton`) beside the output button, which dispatches `.setSleepTimer(SleepTimer.Choice?)`: 15 minutes, 30 minutes, 1 hour, End of track, or `nil` to turn it off. `SleepTimer` (WarbleModel, `SleepTimer/`) in `AppState.sleepTimer` holds the one running and its `deadline`, which joins the store's one timer, so there's none without a timer. A fixed timer's deadline is set when it starts; End of track's is worked out from `PlaybackState.elapsed(at:)`, `duration` and `rate`, again after each report, and a different track reported first counts as the end. At the end of every `reduce`, before `settle`, `followSleepTimer` ends the timer when `AppState.canSetSleepTimer` is false (setting off, Idle, a source gone, or a pause by hand or in the app, which cancels it), and when it's due guesses the pause (`PlaybackState.playing(false, at:)`), asks for the existing `.send(.pause)` and clears it. The button draws the time left from the deadline, like the scrubber, so nothing counts down in the store.
