# Website

Read this before changing `site/` or the user guide. Back to the [architecture index](../../CLAUDE.md#architecture).

`site/` is the Astro site for warble.lorcanchinnock.com, deployed by Cloudflare Workers Builds on every push to `main` (see `site/README.md` › Deploying), so it describes `main`, which can be ahead of the version people can install. The user guide lives in `site/src/guide/`, one Markdown file per page at `/docs/<slug>/`, in file name order. Each file's front matter gives its `title`, a one-line `summary` and its `group` (the groups are in `site/src/lib/guide-files.ts`). Write pages as tasks, in second person: numbered steps, `<kbd>⌘⇧4</kbd>` for keys, and `> [!TIP]` or `> [!NOTE]` callouts. A screenshot of one of Warble's windows takes a title, `![alt](../../../docs/media/settings-notch.png "Caption")`, which puts it on a pastel panel with the title as its caption (`rehypeFigures` in `site/src/lib/guide.ts`). Capture the window at 2× with its transparent corners and no shadow (`screencapture -o -l<window id>`), since the panel draws the shadow and shows the image at half its pixel width. `/changelog/` draws `CHANGELOG.md` as a timeline from its board (#461). `site/src/lib/changelog.ts`, ported from Shot's, parses release-please's file as it is: each release's version and date, its entries as New (features), Fix (bug fixes), Faster or Changed, the commit scope as an area tag in words, and the PR number; `ChangelogRelease.astro` draws one release. The newest eight show, the rest wait behind Show older releases, and Everything, New and Fixes are radio buttons filtered with CSS `:has()`, so the page needs no script. The feed reads the same parser. The landing page's `#install` panel holds the install command, and `/notch-apps/` links to it, so keep that anchor. The steps to open a downloaded zip past Gatekeeper are the FAQ's `#gatekeeper` answer; the install panel links to it, and a short script opens a FAQ answer that a link targets. The command is `site/public/install.sh`, with `site/public/uninstall.sh` beside it, both served as plain text and tested by `make test-install test-uninstall`; keep the commands in the README, the landing page and the guide in line with them. release-please ignores `site/`. The site's look is Warble's own, not Shot's: warm and a little playful, with a cream page, cocoa text, the icon's yellow and pink, a soft serif (Fraunces) for headings, Figtree for text and DM Mono for commands and keys. The notch is the one pure-black thing, as in the app. Light and dark follow the system, and dark is the same palette at night. The fonts come from `@fontsource` packages and are served from the site itself, because the Content-Security-Policy allows only `'self'` and the site makes no third-party requests. The tokens are at the top of `site/src/styles/global.css`. The social card, `site/public/og.png`, is drawn in the same look by `npm run og` (`site/scripts/og.mjs`, which renders HTML with headless Chrome), so rerun it when the headline, the palette or the notch's look changes. It also draws one card per guide page into `site/public/og/<slug>.png`, from each page's title and group, so rerun it and commit the cards when a page is added or retitled; `Base.astro` takes an `image` for a page's own card. For search and sharing, the sitemap (`sitemap.xml.ts`) lists every page with a `lastmod` from git, which it leaves out in a shallow clone, the landing page carries `SoftwareApplication` JSON-LD, the 404 is `noindex`, and `/changelog/rss.xml` turns the same releases into a feed. `/notch-apps/` says what Warble does and doesn't do next to other notch apps. Keep it to claims you can check, with no prices, and update it when Warble gains or drops a feature it mentions. The landing page's notch (`NotchDemo.astro`, with `scripts/notch-demo.ts`) is a working copy hanging from the screen crop (a black bezel, the menu bar and the pastel wallpaper, fading into the page): it opens once by itself a moment after it scrolls into view, then waits for a hover, with no labels or controls around it, only ticks while it is on screen, and does not tour with Reduce motion. It plays nine real songs, the first ODESZA's "A Moment Apart", with their covers in `site/public/media/art-*.webp` and the list in `scripts/notch-demo.ts`; previous, next, shuffle, repeat, the position bar and the volume slider work on them. It draws the housing, wings and open card at the app's own proportions (`NotchLayout`), so change it when they change. It shows only the rest and open states, with no empty state and no captions of its own beyond one line, so keep them in line with the app's. The landing page follows its board on the redesign canvas (#460): the hero with the command as its one action, the working notch, then four numbered chapters, See it, Hear it, Every Mac and Calm, each with the notch in one state hanging from a `ScreenCrop`. `NotchStill.astro` draws those still notches at the app's sizes: resting, open with or without the speaker list, the note, and the notch Warble draws on a display without one. Covers come from `site/public/media/art-*.webp`. After the chapters come a privacy band, a FAQ of `details` elements, and the yellow install panel with the resting notch hanging from its top edge. Only the footer's "LC_" mark and "Made by Lorcan Chinnock", the voice and the copy button carry over from Shot. The shared parts follow the redesign spec's Website polish values (#458). `Base.astro` draws the header (the icon, the name in Fraunces and a Beta badge, then Features, Guide, Changelog, FAQ and GitHub, with the current page on a soft pill) and, under 720 px, puts the links behind a Menu button, a `details` element so it needs no script. The footer has the name and licence, then Product, Help and Project columns, then the maker's mark. `Copy.astro` and the guide's one-line `sh` blocks share one command block: a cocoa bar (`--cmd`) with a yellow `$`, the command on one line that scrolls sideways rather than wrapping, and a cream Copy button as its only action. A grid that holds one needs a `minmax(0, 1fr)` column, or the command's width stretches the page on a phone. `.squig` puts the pink squiggle under one word per heading: with `.now` it draws in once after load, as the hero's does, and otherwise it draws as its heading scrolls into view. `.rise` fades a section up 24 px as it scrolls in. The scrolling ones use CSS scroll timelines. None needs a script, and all are off under Reduce Motion.
