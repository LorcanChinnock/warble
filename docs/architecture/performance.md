# Performance

Read this before changing anything on the hover, expand or play/pause path, or adding a timer. Back to the [architecture index](../../CLAUDE.md#architecture).

`docs/performance.md` holds the budgets, the reference Mac and how each is measured. `Perf` (`Sources/Warble/App/Perf.swift`) emits signposts in category `perf`: `Ready` at launch, and `Expand` and `Play/pause`, which run from the input to the next frame of the display after the change (`Perf.untilNextFrame`, one display link that goes away after it fires), so they cost nothing until someone touches the notch. `scripts/perf.sh` (`make perf-app`) drives the installed WarbleDev with the pointer through `scripts/perf-input.swift`, reads the signposts, and counts CPU and wakeups (context switches, the median 10-second slice) for the app and its Perl processes. A timer shows as wakeups long before it shows as CPU. Its last step turns the waveform on with a launch argument and plays a muted tone, so the tap has audio to hear, and checks the waveform's CPU against the same 0.5% budget; the wakeups there aren't budgeted, since 15 frames a second is the design. `Tests/WarbleCoreTests/PerfTests.swift` (`make perf`) times the stream, artwork colours and idle-card art; `make test` skips it, and CI runs it on the release PR and on any PR labelled `performance`.
